Data

Genome annotations

I have two versions of the annotation from chapter 1, the native ones from the NCBI, and the uniform ones without RNAseq data. I think the best of both worlds would be to use the heterogeneous but RNA-seq supported annotation, to get genes likely to be expressed, and supplement with blast searches against the (nonmasked parts of the) assembly to identify potetially nonexpressed or pseudogenized paralogs.

In order to have species-specific RNA evidence in all annotations, I will make three new ones. A. obtectus, using the E and L expression data and that one larval sample I found, and C. chinensis using expsting expression data from a heatshock experiment from shanxi university. For C. maculatus I will reuse the Lomé RNA based annotation on the superscaffolded assembly. All other species have existing RNAseq annotations. Since the new biopython update breaks the singularity image, I will use braker4 (snakemake wrapper around the braker3 singularity image). it worked very well

Synteny

MCScanX

MCScanX is based on protein synteny from blastp searches. The documentation is not super useful beyond the installation instructions, so I was recommended this workflow, which I will use for detailed instructions, but for preparing the input files, I am using my own scripts and not their provided ones (esp. the perl scripts have hard-coded aspects that assume ncbi assemblies and annotations, which doesn't apply to my data). MCScanX only takes one input: the prefix of both files below ('all_species' in my case). It says directory in the documentation but that's wrong. You run from the same directory as the files are in and the command is just ./MCScanX prefix where the input files are prefix.gff and prefix.blast in the same directory.

  • all_species.gff: I used my script src/make_bedfile_for_MCScanX.py which makes all the files according to the format required, including reformatting the contig names, and also creating a lookup table to associate the new contig names with the original ones from the annotations.
    The files are then all merged with cat *.bed > all_species.gff
  • all_species.blast: I am using blastp according to the above cited workflow on all the species bash/blastp_for_synteny.sh.
    All blast results are again merged cat *.blast > all_species.blast.
Troubleshooting

  • No alighments generated: The log file reads no blast alignments. For me, this was caused by the file extension of the annotation file. I named it .bed but it should be .gff (because it is somehow hardcoded and there is no test to see if a file actually exists?)
  • Some species have no synteny blocks at all in the plot:
    • This has happened when I have included more than one species with annotations from the same pipeline (such as BRAKER3 or 4) with no species name label in the gene IDs. This means that in some pairwise comparisons, labels such as g1.t1 are used for both species, and this causes it to not work for these pairs. It works fine for all others where there are no identical labels between the species, and adding a species-specific prefix to all transcript IDs before blast and in the .gff fixes this.
    • The other possibility is that the geneIDs of the proteinfasta and the annotation don't match. In some cases the proteinfasta IDs have a tailing '_1' that is absent from the geneIDs, and then the software can't associate blast results from the proteinfasta with the annotation. This also gives no error message, just an empty output for all pairwise comparisons involving this species.

Results can be visualized with SynVisio, but its a web application that does not work very well for more than a few species or fragmented assemblies.

Orthologs and Paralogs

Best reciprocal hits

I will use code from chapter III to identify 1-to-1 orthologs, and a new script to plot the pairwise heatmap. The script to get the 1-to-1 orthologs across several species is from the Chapter III revisions where I did the site model testing. It just checks which ortholog pairs are all in a chain of being each others pair mate across all (included) species.

Paralogs

I use all-against-all blastp of protein sequences (same as for synteny and BRH) here and filter for good hits. I use sequence identity > 90%, but Philipp has > 80% and minimum query coverage of 50%. Unsure which is better for this. Philipp also uses blastn with high seq ident thresholds (> 95% and > 99%) to detect amplicon groups on the Y from existing annotated nucleotide sequences.

The original annotation with 441 y-linked transcripts was tested for expressed genes and identifies different numbers depending on if multimapped RNA reads are allowed: 54 (12%) without multimapping, 286 (65%) with multimapping. Philipp does not give details about the expression threshold (x reads in y samples). I have 63 Y-linked genes, and in Chapter IV there are 11 that pass the expression threshold without multimapping (17%).

Amplicon group discovery

Standardized annotations from chapter 1 with no RNAseq evidence (as well as the Kaufmann2023 low-RNAseq-evidence annotation) identify more genes, especially on the Y, most of which are part of an ampliconic group. I suspect they are regions that look similar to existing annotated protein coding regions in my annotation, but have low RNAseq evidence in part due to non-multimapping which means they are filtered from annotations with RNA-seq evidence support. I want to be sure to capture as many duplication events as possible, so I want to find these based on similarity to existing annotated protein sequences. This is a bit complicated since the nucleotide sequence in the assembly includes the introns, but the protein sequence does not.

blast

I will use tblastn to search the existing annotated proteins against the genome they come from to identify potential gene family members that were not annotated. Since the proteins do not contain intron sequences, this would usually create several short alignments per protein for every exon, resulting in low scores, therefore I change some parameters from the default to accomodate based on mean intron lengths (of the assemblies that have intron features annotated, which is all except Bsil and the Diorhabdas, A. obtectus: 4367.07, B. varius: 5880.29, C. chinensis: 2972.9, C. maculatus: 5502.49, resulting in a mean length of 4680.7, I will double it to make sure I get most genes right.)

--max_intron_length 9361 default is 0, no linking across introns, only gives hits for individual exon segments of the protein query. This is not properly splice-aware, but merges everything below the minimum gap length. I will not modify --frame_shift_penalty, since the introns most likely break the frame between exons and penalizing that would work against me.

splice-aware alignment

There is software that properly models introns in the alignment and not just merges gaps below a minimum length like blast:

  • exonerate protein2genome: (Exonerate/2.4.0-GCC-13.3.0 on pelle)
    it is apparently relatively slow and not multithreaded, which makes it inconvenient for the larger assemblies.
    It has a maximum intron length flag, --maxintron and the max. lengths from the annotations are A. obtectus: 496409, B. varius: 497503, C. chinensis: 460962, C. maculatus: 484294, so it should be set it to 500kb. I can't find a proper documentation link
  • miniprot: (miniprot/0.18-GCCcore-13.3.0 on pelle, Git repository)
    I will use the maxintron size described above instead of the default, which would be smaller. It also has pre-trained splice models for insects available.

Miniprot maps each protein query to the assembly on its own and does not consider if other queries map to the same place or if a gene is annotated there. I filter the miniprot output to retain only true amplicons by:

  1. Remove all miniprot alignments that overlap with annotated coding regions (on the same strand)
  2. If there are multiple alignments overlapping in the same region: keep only the best with this priority order:
    • Best sequence identity, but if equal:
    • Longest aligned region, but if equal:
    • A random one
This then leaves a gff with only unique ampliconic regions annotated. The numbers look like that:

Characterize translocation events

Identify translocation events

Since these annotations are not standardized, I have to be careful about using phylogeny-based presence/absence analyses to determine the time and direction of translocations to and from the sex chromosomes. I will still use orthofinder, but I will supplement it with miniprot identified within and across-species paralogs to assure true gene absence when absence is used for translocation inference.

  1. OrthoFinder run with only annotated genes, no miniprot paralogs, to identify across-species gene families. I also include the chinese C. maculatus population in case I want to use it for anything later. I will use the Hierarchical Orthogroups file N0.tsv again and repurpose some of the parsing code I wrote for chapter 1.
  2. Expand OrthoFinder gene families with within-species-miniprot for more gene-family members in each species. This removes preliminary false-positive species-exclusive Y-linkage when an originally autosomal gene family has a miniprot paralog on the Y.
  3. Check gene families for X- and Y-linkage, split by annot-Y-linked, mini-Y-linked etc. Do some summary statistics.
    • Sex-linkage proportion: All Y-linked gene families, how many Y/X/A copies do they have on average?
    • Tandem duplications: What is the mean distance between two members on the same contig?
    • Retrotransposition: How many have no introns on any chromosome category?
    • 'Pseudogenization': How high is the proportion of miniprot-members for all the gene family categories? do Y-linked gene families have more 'pseudogenes'? This is not a certain categorization of pseudogenes! unless there is a very strong signal this is probably not useful!
  4. Try to securely pin the timing of locations to the tree by checking for absence with certainty through between-species miniprot. If a gene family has Y-members in only one species and is Autosome-exclusive in all others this looks like it got translocated onto the Y in this species only, making it recent. I can double-check this assumption through miniprot by mapping all gene family members onto all other species and seeing if there are (good?) hits on the Y.
  5. Predict coding-potential
    Maybe use CPC2 (GitHub, Paper) to assess the coding potential of the annotate genes and varying categories of miniprot hits? This is a bit complicated to run since it needs to use appropriate noncoding-decoys that I need to make, and also is alignment free and trained with existing data, so I need to check how well the training data matches our beetles, since they are pretty far from some model organisms.

Find predictors for gene translocations

Translocations can be influenced by general duplication dynamics, autosomal rearrangements influencing gene family evolution, and sexually antagonistic selection (with sex-biased expression as a proxy)

  • AGORA for ancestral collinearity reconstruction. (Jesper and Filip used that for their PhilTrans paper and recommended it). Github, Paper.
    1. From the abstract: "By comparing successive ancestral genomes along the phylogenetic tree, we estimate the intra- and interchromosomal rearrangement history of all major vertebrate clades at high resolution". Maybe a more SV-oritented supplement to the very individual-translocation oriented approach above.
    2. Check autosomal synteny/collinearity conservation of X/Y-linked orthogroups. When an orthogroup in general is larger and subject to a lot of dynamic rearrangement and tranlsocation, it may become X/Y-linked by chance. Maybe I can test if the sex-linked orthogroups have more/less frequent or extreme rearrangements compared to autosomes in every species?
  • Sex-biased expression in C. maculatus: Maybe check gene-family mean sex-bias of X- or Y- linked gene families. I don't want to get into multimapping here, and sebastians data suggests that gene families mostly follow the same expression direction, so summing all counts from member genes into family-level counts could be a good ending for this part.
  • Relative gene age: Mahajan 2017 use Ka vs. Ks to identify relative gene age, maybe re-use some chapter 3 code?

Whole genome alignments

Alignment with nucmer: technical details and output format

In order to conserve RAM I am setting the minimum match length from the default 20 to 100: nucmer -l 100 --maxmatch. Otherwise it would OOM kill the job even for 200G of ram and that seems excessive.

I run the alignment with nucmer -l 100 --maxmatch and then filter with delta-filter -m -i 50 -l 1000

the output coordinate files have these columns:

    [S1]    Start of the alignment region in the reference sequence.

    [E1]    End of the alignment region in the reference sequence.

    [S2]    Start of the alignment region in the query sequence.

    [E2]    End of the alignment region in the query sequence.

    [LEN 1] Length of the alignment region in the reference sequence,
    measured in nucleotides.

    [LEN 2] Length of the alignment region in the query sequence, measured
    in nucleotides.

    [% IDY] Percent identity of the alignment, calculated as the
    (number of exact matches) / ([LEN 1] + insertions in the query).

    [% SIM] Percent similarity of the alignment, calculated like the above
    value, but counting positive BLOSUM matrix scores instead of exact
    matches.

    [% STP] Percent of stop codons of the alignment, calculated as
    (number of stop codons) / (([LEN 1] + insertions in the query) * 2).

    [LEN R] Length of the reference sequence.

Synteny

The phylogenetic distance of the Diorhabda genus from the Bruchini (see tree in Data) is in agreement with the pairwise synteny analysis presented below. There are chromosomal rearrangements between the Bruchini, but overall synteny is largely conserved, but the greater phylogenetic distance to Diorhabda breaks down synteny between Diorhabda and Bruchini. Within Diorhabda, there are many rearrangements, even though genome size stays largely constant, as opposed to Bruchidius, where genome size changes drastically but synteny stays largely conserved.

The only exception to the eroded synteny between Diorhabda and Bruchini is the X-chromosome, as already identified in chapter III, which maintains synteny across larger phylogenetic distances than any autosomes. Inversely, no Y-chromosome synteny is detected between any of the species. This is potentially due to the high duplication and translocation rates of these genes that make formal synteny difficult do detect.

Species tree

Inconsistency with the NCBI taxonomy

Results agree mostly but not completely with the topological tree in the data summary that uses the NCBI taxonomy. The Data tree has a three-way split at the Bruchini node, with Callosobruchus and Bruchidius both containing two sister species in the genus, but here this is resolved NOT by Bruchidius varius and siliquastri as sister species, instead B. siliquastri splits off at N3, and is not a sister species to B. varius.

The Diorhabda sister species are much more closely related to each other than any other pair. This also shows up in the Y-protein synteny in the circos plots above, but it is really clear here, they are about as close as the two C. maculatus populations.

Orthofinder gives a tree with branch support that indicates what proportion of gene trees support any node split. Note that the N3 and N4 nodes that are problematic above also have a lower support than the rest. It seems like this is a complicated taxonomy to resolve

We have decided to move on with the orthofinder tree as-is and not try to adjust it to match the NCBI taxonomy. There are two reasons: The first is that NCBI taxonomy can be wrong or outdated in some cases, the other is that the problematic nodes have lower branch support anyways, indicating that this would be difficult and time intensive to investigate. Since my defense is soon and this is not at all the focus of the study, I will just accept the orthofinder tree for now.

Translocation dynamics

Do the sex chromosomes contain mostly the same or different orthogroups?

The synteny indicates that the X chromosomes likely contain many of the same orthogroups across species, while the Y chromosomes are unique between species. I check this specifically with UpSet plots describing the intersection of species-presence (and absence) of orthogroups.

The orthogroups include the longest isoform of all proteins annotated in the gff by default, as well as unplaced genes, they are treated as single-gene orthogroups (tab only gff annotation). I will expand the orthofinder orthogroups by also including the miniprot paralogs identified by the within-species miniprot search (tab including miniprot paralogs). They are unique paralogs not overlapping with already annotated genes or paralogs from other genes (see filtering and numbers summary in the relevant method section). Note that the numbers here are kind of 'inverse' to the sex-linked genes above, the Diorhabda genus has few paralogs, the other species many. Several single-member orthogroups also have miniprot paralogs, making them multi-member orthogroups still confined to one species.
